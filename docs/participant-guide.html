AI와 만드는 우리 동네 지도

각자 자신이 사는 동네에서 가로 1km × 세로 1km 구역을 고르고, AI가 작성한 수집 코드를 실행해 그 구역의 OSM·Overture 데이터를 받습니다. 수집한 지도를 입체로 그리고 화풍을 입힌 뒤 브라우저에서 이동·확대하는 지도로 완성합니다.

이 실습에서는 공유받은 저장소에서 AI와 코드를 만들고 직접 실행합니다. 지도 제작 완성 코드는 제공하지 않습니다. 기본 목표는 로컬에서 이동·확대할 수 있는 낮 지도입니다. 야경·실제 지형·인터넷 공개는 선택 과제입니다.

이번 핸즈온에서 만들 것

각자 사는 동네의 지도 데이터를 입체 그림으로 바꾸고, 브라우저에서 이동·확대할 수 있는 지도로 만듭니다. 처음부터 모든 선택을 할 필요는 없습니다. 동네 중심은 OSM을 살펴보는 1단계에서 정하고, 화풍은 이미지를 편집하는 4단계에서 정합니다.

  1. 환경 준비: 저장소 안에 도구를 설치하고 이미지 편집 모델을 미리 받습니다.
  2. 동네 데이터 수집: OpenStreetMap에서 동네 중심을 고르고, 그 1km × 1km 범위의 OSM·Overture 자료를 모읍니다.
  3. 지도 만들기: 데이터를 정리해 bin으로 굽고, three.js로 그려 타일 이미지를 촬영합니다.
  4. 그림으로 바꾸기: 이때 원하는 화풍을 정하고, 맥에서 MFLUX로 이미지를 편집합니다.
  5. 웹 지도 완성: 결과 타일을 확인·합성해 브라우저 지도에 올립니다.

  • 실제 지형: 해당 지역 DEM을 확보한 뒤 AI와 좌표계·고도 단위를 확인합니다. 이후 엔진·촬영·마스크에 같은 지형을 사용해야 합니다.

자료가 없다면 평면과 임시 높이로 기본 실습을 계속합니다.

실습 서버에서 필요한 파일만 HTTP로 제공하고 pnpm run dev로 실행하게 해.

상세 타일이 오기 전에는 확보된 낮은 해상도로 대체해.
중복 요청·요청 동시 수를 관리하고 필요 없어진 요청은 취소해.
오래 사용하지 않은 이미지·GPU 텍스처를 해제해.
404·느린 응답·깨진 이미지가 전체 지도를 멈추거나 무한 재시도를 만들지 않게 해.
측정된 문제가 없으면 원작 규모의 최적화를 미리 만들지 마.

불빛을 만들었다면 낮 그림을 어둡게 한 뒤 같은 위치에 불빛을 더해.
sources.md에서 실제 사용한 출처와 필요한 고지를 읽어 화면에 표시해.
README에 시작·종료·재생성 방법, reports/viewer.md에 검증 결과를 남겨.
R2 업로드·공개 배포는 아직 수행하지 마.

실행

서버가 이미 켜져 있으면 같은 포트로 다시 실행하지 말고 기존 서버를 사용하세요.

bash scripts/run.sh pnpm run dev

브라우저에서 http://localhost:5173을 열고 아래를 확인하세요.

  • 그림이 엔진의 건물·도로 위치와 맞습니다.
  • 드래그 이동·확대·축소 중 빈칸이나 큰 위치 변화가 없습니다.
  • 새로고침해도 같은 지도가 열립니다.
  • 로딩 실패가 나면 원인을 알 수 있고 나머지 지도가 유지됩니다.
  • 지도를 오랫동안 이동해도 이미지·텍스처가 무한히 쌓이지 않습니다.
  • 선택한 야경에서는 낮 타일과 불빛이 맞습니다.
  • 실제 데이터·모델·도구에 필요한 출처 표시가 있습니다.

서버를 종료하려면 실행 중인 터미널에서 Ctrl+C를 누릅니다.

9. 선택 과제: 인터넷에 공개하기

목표: 로컬에서 완성한 지도와 타일을 배포해, 다른 사람이 접속할 수 있는 공개 주소에서 지도를 사용하게 합니다.

결과물: 공개 웹 주소와 타일 제공 주소, 배포·갱신 방법

로컬 완료 후 진행합니다. R2는 타일 저장·제공용이며 AI 처리 도구가 아닙니다.

참가자가 할 일

공개 여부와 서비스를 정하세요. 로그인·본인 인증·필요한 결제 설정은 직접 합니다. 비밀 키는 AI 대화에 붙이지 말고 로컬 환경에 입력하세요.

AI 요청문 — 선택한 서비스에 맞는 배포 준비

어떤 파일을 어디에 올릴지, 타일 URL·CORS를 어떻게 설정할지 정하고 배포 파일·명령을 준비하는 요청입니다. 로그인과 실제 배포는 참가자가 이어서 수행합니다.

내가 선택한 스토리지는 [서비스], 웹 호스팅은 [서비스]야.
현재 output/manifest.json·타일과 웹 코드를 읽고 실제 공식 배포 방법을 확인해.
필요한 배포 파일·업로드 명령·CORS·타일 URL 설정을 준비해.
계정 로그인과 비밀 키 입력은 내가 직접 하게 안내하고 비밀정보를 요구하지 마.
어떤 파일이 어디에 공개되는지 설명하고, 내가 실행할 명령과 확인할 주소를 알려줘.
지금은 실제 업로드나 배포를 실행하지 마.

참가자가 실행하고 확인

  1. R2 또는 선택한 정적 스토리지 계정과 웹 호스팅을 준비합니다.
  2. 타일·manifest는 스토리지에, HTML·JavaScript는 웹 호스팅에 배치합니다. 실제 URL 구조를 확인합니다.
  3. 웹페이지와 타일의 출처가 다르면 CORS를 설정합니다. 관리용 비밀 키를 브라우저에 넣지 않습니다.
  4. 수정 파일이 갱신되도록 버전 경로나 캐시 무효화 방식을 정합니다.
  5. 공개 주소에서 이동·확대·선택한 야경과 출처 표시를 확인합니다.
  6. 모바일 공개라면 실제 폰에서 터치·고해상도·메모리·야경을 확인합니다.

공급자마다 배포 명령이 다르므로 실제 선택한 도구의 공식 안내로 확정합니다. 계정이나 결제 수단이 없으면 로컬 완료로 기록하고 공개 주소를 만들었다고 적지 마세요.

실습이 끝나면 설치 항목 정리하기

목표: 작성한 코드·지도·이미지는 남기고, 이번 실습이 설치한 도구·모델·캐시를 제거합니다.

참가자가 직접 할 일: 남길 결과물을 확인하고 아래 종료·삭제 순서를 수행합니다. AI는 삭제 계획 설명과 오류 해결만 돕습니다.

서버와 이미지 편집 작업을 종료한 뒤, 저장소에서 삭제 계획을 확인하세요.

bash scripts/uninstall.sh

삭제할 항목을 확인한 뒤 실행합니다.

bash scripts/uninstall.sh --yes

셋업이 소유한 .tools·.venv·node_modules·.cache를 삭제합니다. 기존 전역 도구와 작성한 코드·지도·이미지·보고서는 남습니다. 소유 기록이 없으면 삭제하지 않으며, 기록을 임의로 만들면 안 됩니다.

삭제 후 현재 터미널을 닫으세요. 작업 폴더와 AI가 만든 scripts/run.sh는 남습니다.

나중에 이어서 실습하려면 새 터미널에서 같은 저장소로 이동해 실행하세요.

bash scripts/setup.sh

도구 설치가 끝나면 bash scripts/run.sh pnpm run setup:model로 지운 모델을 다시 받습니다. 작성한 코드와 남겨둔 데이터·이미지는 그대로 이어서 사용합니다.
