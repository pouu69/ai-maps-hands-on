AI와 만드는 우리 동네 지도

각자 자신이 사는 동네에서 가로 1km × 세로 1km 구역을 고르고, AI가 작성한 수집 코드를 실행해 그 구역의 OSM·Overture 데이터를 받습니다. 수집한 지도를 입체로 그리고 화풍을 입힌 뒤 브라우저에서 회전·이동·확대하는 3D 지도로 완성합니다.

이 실습에서는 공유받은 저장소에서 AI가 코드를 작성·실행하고 참가자는 결과를 확인합니다. 지도 제작 완성 코드는 제공하지 않습니다. 기본 목표는 촬영 당시 보였던 3D 표면에 AI 그림을 텍스처로 투영한 지도입니다. 브라우저에서 회전·기울기 조절·이동·확대·축소할 수 있습니다. 야경·실제 지형은 선택 과제입니다.

이번 핸즈온에서 만들 것

각자 사는 동네의 지도 데이터와 AI 그림으로 회전 가능한 3D 지도를 만듭니다. 처음부터 모든 선택을 할 필요는 없습니다. 동네 중심은 OSM을 살펴보는 1단계에서 정하고, 화풍은 이미지를 편집하는 4단계에서 정합니다.

  1. 환경 준비: 저장소 안에 도구를 설치하고 이미지 편집 모델을 미리 받습니다.
  2. 동네 데이터 수집: OpenStreetMap에서 동네 중심을 고르고, 그 1km × 1km 범위의 OSM·Overture 자료를 모읍니다.
  3. 지도 만들기: 데이터를 정리해 bin으로 굽고, three.js로 그려 타일 이미지를 촬영합니다.
  4. 그림으로 바꾸기: 이때 원하는 화풍을 정하고, 맥에서 MFLUX로 이미지를 편집합니다.
  5. 웹 지도 완성: 결과 이미지를 타일로 만들고, 원본 3D 장면의 깊이를 이용해 촬영에 보였던 표면에만 그림을 입힙니다.

3D와 AI 그림의 역할: three.js는 실제 건물·도로의 3D 메시를 렌더링하고, MFLUX는 촬영한 2D 이미지의 화풍을 바꿉니다. 마지막에는 이 그림을 촬영 당시 보였던 지붕·벽·지면에 투영합니다. 뒤쪽이나 다른 건물에 가렸던 부분은 기본 재질로 남습니다. 회전하면 그림과 기본 재질의 경계가 보이고, 그림 속 그림자는 그대로 남습니다.

카메라는 역할을 나눕니다. 그림을 입힐 기준인 ‘촬영 카메라’는 고정합니다. 브라우저의 ‘탐색 카메라’는 자유롭게 움직이며, 회전해도 그림은 같은 3D 표면에 붙어 있습니다.

4. 회전·적용 영역 검증
원본 재질·그림 적용·적용 영역 표시를 전환하고 촬영 시점 복귀 버튼을 제공해.
탐색 카메라는 회전·기울기 조절·이동·확대·축소할 수 있게 해.
실제 서버·브라우저에서 촬영 시점, 옆쪽, 반대쪽을 확인해.
촬영 시점의 지붕·도로 정렬, 회전 중 그림의 표면 고정,
뒤 건물·뒷벽의 기본 재질, 투명/범위 밖의 기본 재질을 각각 검사해.
이미지 형태 오류를 투영으로 복구했다고 기록하지 마.
reports/projection.md와 progress.md에 결과·미확인 항목을 남기고 HTTP 주소를 알려줘.
한 타일의 검사를 통과하기 전에는 전체 타일로 확대하지 마.

완료 기준: AI가 앞뒤 표면의 적용·제외를 검사했고, 브라우저에서 회전해도 그림이 같은 표면에 붙어 있습니다. 촬영에 보이지 않았던 부분은 기본 재질입니다.

8-3. 전체 지도와 탐색 조작 연결하기

목표: 검증한 투영 재질을 전체 구역에 적용하고 로딩·오류·출처 표시를 마무리합니다.

AI 요청문 설명: 한 타일에서 확인한 방식으로 전체 그림을 연결합니다. 1km 범위는 타일을 하나의 큰 텍스처인 ‘아틀라스’로 묶어 사용하고, 실제 GPU의 크기·메모리 한도를 확인합니다.

8-2에서 검증한 투영 재질을 전체 구역에 연결해.

1. 아틀라스 구성·GPU 한도 확인
output/manifest.json의 최고 해상도 격자에 맞춰 그림 타일을 색 아틀라스로 묶고,
같은 치수의 depth.f32를 깊이 아틀라스로 사용해. 빈 픽셀은 투명/무효값을 유지해.
타일마다 별도 텍스처를 셰이더에 무제한 연결하지 마.
실제 GPU의 최대 텍스처 크기·깊이 텍스처 지원·예상 메모리를 먼저 확인해.
한도를 초과하면 조용히 해상도를 바꾸지 말고 원인과 분할 방안을 보고해.
그때도 기본 재질의 3D 화면은 사용할 수 있게 해.

2. 전체 구역 투영
세계 좌표→그림 픽셀→아틀라스 UV 변환은 8-2와 같은 구현을 사용해.
그림의 낮은 해상도로 먼저 표시할 수 있지만 깊이를 평균 낸 값으로 대체하지 마.
탐색 카메라의 확대·회전으로 촬영 기준이나 깊이를 다시 만들지 마.
형상·촬영 기준·최고 해상도 격자가 바뀌면 해시 불일치를 보고하고 잘못된 투영을 중단해.
단순 화풍 변경만으로 형상 깊이를 무효화하지 마.

3. 로딩 실패·자원 관리
깊이를 못 읽으면 투영을 끄고 기본 재질로 표시해.
색 타일의 404·느린 응답·깨진 파일은 해당 영역을 기본 재질로 표시해.
중복 요청·요청 동시 수·재시도 횟수를 제한하고, 교체한 이미지·GPU 자원을 해제해.

4. 탐색 조작·불빛 검증
원본 재질·그림 적용·적용 영역 표시와 촬영 시점 복귀를 전체 지도에서도 유지해.
회전·기울기 조절·이동·확대·축소와 새로고침을 실제로 확인해.
촬영 시점 및 옆/반대 시점, 투명 경계·타일 연결부를 확인하고,
타일 실패·깊이 누락·해시 불일치를 재현해 기본 재질로 돌아오는지도 검사해.
불빛을 만들었다면 동일한 UV·깊이·표면 방향 조건으로 표면의 발광 색에 더해.
불빛을 화면 위에 덮거나 촬영에 가렸던 벽에 적용하지 마.
sources.md에서 실제 사용한 출처와 필요한 고지를 읽어 화면에 표시해.

5. 서버 실행·결과 기록
기존 서버가 있으면 같은 프로젝트인지 확인해 재사용하고, 없으면 직접 실행해.
필요한 실습 파일만 HTTP로 제공하고 접속 URL을 알려줘.
README에 시작·종료·재생성 방법, reports/viewer.md와 progress.md에 실제 검증 결과를 남겨.

결과 확인

AI가 안내한 HTTP 주소를 브라우저에서 열고 아래를 확인하세요.

  • 촬영 시점에서 그림이 원본 건물·도로의 위치와 맞습니다.
  • 회전·기울기 조절·이동·확대·축소해도 그림이 같은 표면에 붙어 있습니다.
  • 뒤쪽·가려졌던 면은 기본 재질이며 앞 건물의 그림이 붙지 않습니다.
  • 원본 재질·그림 적용·적용 영역 표시와 촬영 시점 복귀가 동작합니다.
  • 새로고침해도 같은 지도가 열립니다.
  • 로딩 실패가 나면 원인을 알 수 있고 나머지 지도가 유지됩니다.
  • 지도를 오랫동안 이동해도 이미지·텍스처가 무한히 쌓이지 않습니다.
  • 선택한 야경에서는 불빛도 같은 3D 표면에 붙어 있습니다.
  • 실제 데이터·모델·도구에 필요한 출처 표시가 있습니다.

서버를 종료할 때는 AI에게 실행 중인 실습 서버를 종료해 달라고 요청하세요.

실습이 끝나면 설치 항목 정리하기

목표: 작성한 코드·지도·이미지는 남기고, 이번 실습이 설치한 도구·모델·캐시를 제거합니다.

참가자가 직접 할 일: 남길 결과물을 확인하고 아래 종료·삭제 순서를 수행합니다. AI는 삭제 계획 설명과 오류 해결만 돕습니다.

서버와 이미지 편집 작업을 종료한 뒤, 저장소에서 삭제 계획을 확인하세요.

bash scripts/uninstall.sh

삭제할 항목을 확인한 뒤 실행합니다.

bash scripts/uninstall.sh --yes

셋업이 소유한 .tools·.venv·node_modules·.cache를 삭제합니다. 기존 전역 도구와 작성한 코드·지도·이미지·보고서는 남습니다. 소유 기록이 없으면 삭제하지 않으며, 기록을 임의로 만들면 안 됩니다.

삭제 후 현재 터미널을 닫으세요. 작업 폴더와 AI가 만든 scripts/run.sh는 남습니다.

나중에 이어서 실습하려면 새 터미널에서 같은 저장소로 이동해 실행하세요.

bash scripts/setup.sh

도구 설치가 끝나면 bash scripts/run.sh pnpm run setup:model로 지운 모델을 다시 받습니다. 작성한 코드와 남겨둔 데이터·이미지는 그대로 이어서 사용합니다.
